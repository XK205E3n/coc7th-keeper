### T-A7 · 断点令牌：加警告注释或删除 —— **P2**

**文件**：`frontend/src/style.css:16-17`

```css
/* 现状 */
--bp-mobile: 640px;
--bp-tablet: 1024px;
```

**问题**：这两个令牌**全仓 0 处引用**，且按本项目已确认的规则，`var()` **不能用于 `@media` 查询**（浏览器不解析 + Vite/lightningcss 压缩报 `Invalid media query` 直接导致 `npm run build` 失败）。也就是说这俩令牌**永远无法被消费**，是纯地雷 —— 下一个接手的 AI 大概率会拿去用然后炸构建。

**二选一（推荐前者）**：

- **方案 1（推荐）保留 + 警告注释**：
  ```css
  /* ⚠️ 仅作断点契约的集中声明，禁止在 @media 中使用 var() —— 浏览器不解析且
     lightningcss 压缩会报 Invalid media query 导致 build 失败。
     媒体查询请写字面量 640px / 1024px。 */
  --bp-mobile: 640px;
  --bp-tablet: 1024px;
  ```
- **方案 2 删除**这两行，断点契约只写在 CHANGELOG / 本任务书里。

选哪个都行，**但不能保持现状（裸声明无说明）**。完成报告里写明选了哪个。

**DoD**：`grep -rn "bp-mobile\|bp-tablet" frontend/src` 只剩声明处（或为 0）；`npm run build` 通过。

### T-A8 · `EmptyState.vue` 插槽 `v-if` 顺序 —— **P3**

**文件**：`frontend/src/components/EmptyState.vue:25-30`

```vue
<!-- 现状：to 在前，actionLabel 在后 -->
<n-button v-if="to" ...>{{ actionLabel }}</n-button>
<n-button v-else-if="actionLabel" ...>{{ actionLabel }}</n-button>
```

**问题**：若调用方只传 `to` 而不传 `actionLabel`，会渲染一个**空标题按钮**。原来的外层 `v-if="actionLabel"` 包裹能防住，改插槽后防丢了。

**当前不触发** —— 5 个调用点都成对传参（CharacterBar / Admin / Characters / Content / Overview）。属于脆弱写法，不是活跃 bug。

**改法**（外层用 `actionLabel` 把关，内层判 `to`）：

```vue
<template #extra>
  <template v-if="actionLabel">
    <n-button v-if="to" type="primary" size="small" @click="$router.push(to)">{{ actionLabel }}</n-button>
    <n-button v-else type="primary" size="small" @click="onClick">{{ actionLabel }}</n-button>
  </template>
</template>
```

**DoD**：CDP 断言 5 个空状态按钮仍在 `.n-empty` 内部、文案正常；`npm run build` 通过。

### T-A12 · `Admin.vue` 资源按钮 loading 仍同步 —— **P2，上一轮 DoD 未真正达成**

**文件**：`frontend/src/views/Admin.vue:29-37`（`RESOURCES`）、`:80-89`（`onResource`）、`:133-143`（模板）

**问题**：上一轮 T-A5.3 把单个 `loading` 拆成 `loadingList / loadingRoom / loadingResource` 三个 ref，完成报告称「9 个按钮不再同步 spinner」——**该表述与实测不符**。

`RESOURCES` 共 **7 项**（messages / kp_notes / dice_log / state_changes / perceptions / llm_log / clues），模板里 7 个按钮**全部绑定同一个 `loadingResource`**（`Admin.vue:136`）。点任意一个资源按钮，**7 个一起转圈**。实际达成的是「3 组不同步」，第 3 组内部仍然同步。

面板只有 9 个按钮，其中 7 个共享一个 spinner，视觉上等于「点一下满屏转」，正是 T-A5.3 原本要修的现象。

**改法**（把资源 loading 从布尔改成"当前正在查哪个 key"）：

```ts
// 现状
const loadingResource = ref(false)
// 改为
const loadingResource = ref<DevResource | null>(null)
```

```ts
async function onResource(res: DevResource): Promise<void> {
  if (!gameKey.value.trim()) { message.warning('请输入游戏号'); return }
  loadingResource.value = res
  try { /* 不变 */ }
  finally { loadingResource.value = null }
}
```

```vue
<!-- 模板 Admin.vue:136 -->
:loading="loadingResource === r.key"
```

`finally` 里置 `null`（不是 `false`），保证异常路径也解锁。

**DoD**：
- CDP 断言：点「叙事流消息」时，仅该按钮 `aria-busy="true"` / 带 `n-button--loading` class，其余 6 个不带；`kp_notes` 同理
- 三个查询（列出房间 / 房间概览 / 任一资源）互不干扰
