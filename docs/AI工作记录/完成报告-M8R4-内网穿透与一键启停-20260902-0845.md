## 3. 实现说明（偏差与依据）

- **穿透进程重定向**：`Start-BackgroundCommand` 用 `Start-Process -RedirectStandardOutput $LogFile -RedirectStandardError $LogFile` 把 stdout+stderr **合并到同一文件** `data/.run/tunnel.log`（无 `.err` 拆分），与任务书「都重定向到 tunnel.log」字面要求一致；`Wait-TunnelUrl` 只读该单文件即可抓到打在 stderr 的 cloudflared URL。**初版报告误写成 stderr→`tunnel.log.err` 的「安全偏差」，实际代码从未拆分，此处更正。**
- **cloudflared/cpolar 分支启动签名修正**：初版两分支用旧的 `-Command $cmd` 调 `Start-BackgroundCommand`，而该函数签名已改为 `-FilePath`/`-Arguments`（直接二进制启动，规避 cmd.exe 被安全策略拦截）。已改为 `-FilePath $bin -Arguments "tunnel --url ..."` / `"http $port"`，与 frp 分支一致；否则本机原生运行会在参数绑定时失败（`mock` 分支不启进程，故 T-D6 等价验证未触发此 bug）。
- **PS1 文件编码修正（BOM）**：`stop-web.ps1`/`status-web.ps1` 初版为 UTF-8 无 BOM，在本机中文 locale（GBK 936）下 PowerShell 5.1 解析器会误读中文注释、报「缺少 } / 数组索引」等空 extent 伪错误 —— 初检「3 脚本 SYNTAX_OK」是**误报**。已用 UTF-8 BOM 重写，现三脚本 `Parser.ParseFile` 均 `SYNTAX_OK`（见 §5）。
- **`start-web.bat` 委派 ps1**：`-daemon`/`-tunnel` 通过 `powershell -ExecutionPolicy Bypass -File start-web.ps1` 实现，避免 cmd 重写脆弱逻辑；默认/`-dev` 保持原生。
- **`-Provider` 运行期覆盖**：任务书 T-D1 说 `-Tunnel` 可临时覆盖 `enabled`；本实现额外支持 `-Provider <name>` 临时覆盖 provider（不写回配置），便于自测与切换，属合理扩展。
- **`data/config.json` 测试产物清理**：自测脚本写入的 `share_url` 与 `tunnel` 段已还原（见 §2 清理行），交付时 `data/config.json` 保持任务书前原状（git 亦忽略 `data/`）。
