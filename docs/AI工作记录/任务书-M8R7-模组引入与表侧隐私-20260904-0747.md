# 任务书 · M8R7 模组引入体验与表侧隐私（sleeping-cat 实测转化）

> 提出人：E3n（模组实测反馈）｜执行：工作 agent｜时点：2026-09-04 07:47（北京时间）
> 上游背景：M8R5/M8R6 已完成；E3n 实测模组（含《不要叫醒沉睡的猫》）后反馈两大类问题。

## 1. 问题描述（E3n 原话归纳）

1. **开场引入简陋**：进游戏后调查员完全不知道自己**为什么来**、**怎么来的**、**为什么出现在缆车上**——页面直接把 `scenes.json` 首场景的 `summary`（KP 视角梗概，说明文体）原样亮出来。
2. **玩家界面泄漏 KP 信息**：界面显示了不应该由玩家知道的信息。

## 2. 实测取证（修复前，浏览器 + 真实 LLM 四轮结算）

- 开场消息与场景栏展示 s01 summary 全文，其中含「需要 SAN 1/1D4（计入『习惯恐惧』规则）」「不明黑色物体（**筑巢冷蛛的腹部**）」「必须在到站前跳下（**【跳跃】检定**）」等 KP 内容（截图 `.tmp/round-shots/01`）。
- 首场景玩家资料手卡（sms-worrying / sns-short-posts）**没有**随开场发放。
- `/api/modules/{id}/scenes` 向任意玩家端返回全部场景的 `summary / checks / clues / npcs / next`；后续场景名直接剧透（"引开冷蛛""冷蛛袭来 / 石像归位""终末 / 切断连接"）。
- `/api/modules` 的 meta 含 `summary`（完整通关路线）、`tags`（"冷蛛""幻梦境"）、`source.notes`（"归还石像为通关目标"）。
- 内容页（Content.vue）渲染 `meta.summary` + 全部场景名链。

## 3. 改动要求（DoD）

1. 玩家边界投影：`/api/modules(/detail)`、`/api/modules/{id}/scenes(/detail)`、`scene_changed` 广播只发表侧字段（`id / name / location / intro / handouts`；meta 剥 `summary / tags / source`）。**AI 守密人上下文仍读全量场景对象，不受影响。**
2. 开场白：首场景新增玩家可见 `intro`（交代为什么来 / 怎么来的 / 现在在哪），开场消息用 intro（缺失时仅表头，绝不回退 summary）；首场景 handouts 随开场注入叙事流。
3. sleeping-cat 模组补全：8 个场景全部写 `intro`；场景名表侧化（去怪物名/结局词）；meta 补 `public_summary`（无剧透简介）。其余三模组补 `public_summary`。
   - **变更（2026-09-04，E3n 追加指令）**：按同一审查逻辑扩展到**全部模组**——the-haunting / toy-dancer-comes / yuren-pie 也补 intro ×全场景 + 场景名/地点表侧化 + 玩家视角通读终检；测试同步泛化为全模组断言。
4. 前端：SceneBar / 开场 / scene_changed 消息只展示表侧内容；内容页展示 `public_summary`（缺失则占位提示），场景名链不再展示。
5. 顺带修复实测中撞见的 `advanceRound` 写死 `X-Host-Token`：M8R5 定案"全员提交后人人可点推进"，非房主玩家点击应成功（实测 401）。
6. 新增 pytest 覆盖投影契约与开场隐私；更新模组拆解说明（intro / public_summary 字段规范 + intro 写作规范 + 校验清单项）。

## 4. 铁律与边界

- `server/engine/**`、SSE 总线机制、`run_round` 管线顺序不动（本轮未触及）。
- reasoning_content / kp_notes 不外泄的既有铁律继续生效；本轮是把它延伸到"模组静态数据"边界。
- 改动留工作区不提交，等复核与授权。
