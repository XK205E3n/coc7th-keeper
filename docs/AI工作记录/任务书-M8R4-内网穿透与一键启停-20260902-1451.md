### T-D1 · 穿透配置层

**文件**：`server/config.py`（只改 `DEFAULT_CONFIG`，**不改任何读写逻辑**）

```python
"tunnel": {
    "enabled": False,              # 全局开关；命令行 -Tunnel 可临时覆盖（不写回）
    "provider": "cloudflared",     # cloudflared | frp | cpolar | mock
    "target_port": None,           # 穿透目标端口；None = 取 server.port（默认 18000）
    "cloudflared": {"bin": "cloudflared", "tunnel_name": None, "protocol": "http2"},
    "frp": {"bin": "frpc", "config": "tools/frpc.toml"},
    "cpolar": {"bin": "cpolar", "region": "cn"},
    "mock": {"url": "https://mock-abcdef.trycloudflare.com"},  # 自测用，见 T-D6
},
```

**约束**：
- 只加这一段默认值，**不要**改 `load_config` / `save_config` / `_merge`（深合并已覆盖，老配置缺失 `tunnel` 会自动取默认）
- `_normalise()` 里**不要**加 tunnel 相关强校验（会让老配置报错）

### T-D2 · 一键启动脚本增强

**文件**：`start-web.ps1`、`start-web.bat`

**四种模式（必须向后兼容）**：

| 命令 | 行为 |
|------|------|
| `start-web.ps1` | **前台阻塞**，无穿透 —— 与现状完全一致，不得改变 |
| `start-web.ps1 -Daemon` | 后台起后端，无穿透，脚本打印 PID 后**退出** |
| `start-web.ps1 -Tunnel` | 后台：后端 **+** 穿透，抓到公网 URL → 写 `share_url` → 打印 → 脚本退出 |
| `start-web.ps1 -Dev` | 开发模式（vite），**保持现状** |

**`-Dev` 与 `-Tunnel` 同时传 → 直接报错退出**，错误信息写清楚：
> 开发模式前端跑在 Vite(5173)，穿透 18000 只能暴露 API、拿不到前端资源且跨域。请先 `npm run build` 再用 `-Tunnel`。

**进程与日志约定**：
- PID 文件：`data/.run/backend.pid`、`data/.run/tunnel.pid`、`data/.run/frontend.pid`
- 日志：`data/.run/backend.log`、`data/.run/tunnel.log`
- 目录不存在时自动创建

**`-Tunnel` 的启动顺序（严格按序，前一步失败即退出并清理已起进程）**：
1. 检查 `.venv` 存在（沿用现状逻辑）
2. 检查前端产物 `frontend/dist/index.html`（沿用现状的首次自动构建）
3. **安全检查**：读 config，若 `access_password` 为空 → 红色警告：
   ```
   [警告] access_password 未设置 —— 穿透后公网任何人可进入你的房间。
          建议先在 data/config.json 设置 access_password，或加 -Force 跳过。
   ```
   无 `-Force` 时**等待用户确认**（`Read-Host`），非交互环境视为拒绝
4. 后台起后端（隐藏窗口），轮询 `GET /api/health` 等就绪（超时 30s）
5. 起穿透进程（见 T-D3）
6. 抓公网 URL（见 T-D4），写入 `config["share_url"]` 并 `save_config()`
7. 打印汇总：本地地址、公网地址、PID、以及「关闭命令：`.\stop-web.ps1`」

**`-Daemon`**：只做 1/2/4，不做 3/5/6/7。

### T-D3 · 穿透 provider 适配

按 `tunnel.provider` 分发。**provider 二进制不存在时，必须明确报错 + 给安装指引，禁止静默跳过或降级。**

| provider | 启动命令 | URL 来源 |
|----------|----------|----------|
| `cloudflared` | `cloudflared tunnel --url http://127.0.0.1:<port>` | **stderr**，正则 `https://[A-Za-z0-9-]+\.trycloudflare\.com` |
| `frp` | `frpc -c <config>`（默认 `tools/frpc.toml`） | 优先从 `tools/frpc.toml` 的 `subdomain` / `customDomains` 拼；拼不出来则抓日志 |
| `cpolar` | `cpolar http <port>` | 抓日志；若本地有 ngrok 风格 API（`http://127.0.0.1:4040/api/tunnels`）优先用。**具体端口与返回结构需实跑确认，确认不了就在完成报告里记为已知限制** |
| `mock` | 不启真进程，直接返回 `tunnel.mock.url` | 配置值 —— **自测用的逃生舱**，见 T-D6 |

**通用要求**：
- 穿透进程的 stdout **和 stderr 都重定向到 `data/.run/tunnel.log`** —— cloudflared 的 URL 打在 stderr，只接 stdout 会永远抓不到
- 进程用隐藏窗口后台启动，PID 写入 `data/.run/tunnel.pid`

**`tools/frpc.toml` 模板**（新建，不要填真实密钥）：
```toml
serverAddr = "<你的 frps 地址>"
serverPort = 7000
auth.token = "<填你的 token，此文件请勿提交真实值>"

[[proxies]]
name = "coc7th-web"
type = "http"
localIP = "127.0.0.1"
localPort = 18000
# 二选一：
# subdomain = "coc"                    # → http://coc.<你的 frps 域名>
# customDomains = ["coc.example.com"]  # → 需要域名 A 记录指向 frps
```

### T-D4 · 公网 URL 抓取与回写

写一个 **`Wait-TunnelUrl`** 函数（PowerShell）或等价实现：
- 轮询 `data/.run/tunnel.log`，用 provider 对应正则提取 HTTPS URL
- 轮询间隔 1s，超时 **60s** 后报错并关闭穿透进程
- 抓到后：`cfg = load_config()` → `cfg["share_url"] = url` → `save_config(cfg)`
- 同时打印到控制台

**注意**：`save_config()` 会整体重写 `config.json`（带 `indent=2`）。写回前用 `load_config()` 拿全量配置再改字段，**不要**自己拼 JSON 覆盖（会丢字段、破坏用户已有配置）。

**单测要求**：把 URL 抓取的正则逻辑做成可独立验证的形式，用样例日志文本测至少 3 例：
1. cloudflared 标准输出行
2. 日志里夹带 ANSI 颜色码的情况（cloudflared 带颜色输出）
3. 多行噪声中只有一行含 URL

### T-D5 · 一键关闭脚本

**新建**：`stop-web.ps1`、`stop-web.bat`

**要求**：
1. 按 `data/.run/*.pid` 逐个关闭，**必须树杀**：
   - PowerShell：`Stop-Process -Id $pid -Force -ErrorAction SilentlyContinue` **不够**（杀不掉子进程）
   - 用 `taskkill /PID <pid> /T /F`（`/T` 是关键，杀进程树）
2. **兜底清理**：PID 文件缺失/失效时，按进程名兜底（`python.exe` 跑 main.py 的、**不要**无差别杀所有 python）、`cloudflared`、`frpc`、`cpolar`、`vite`/`node`
3. **幂等**：重复执行不报错，打印「无运行中进程」
4. 清理 `data/.run/` 下的 pid 文件（日志保留，便于排查）
5. 关闭后打印确认信息

**兜底杀进程的安全红线**：
- **禁止** `Stop-Process -Name python -Force`（会误杀用户其它 Python 程序）
- 只允许：按 PID（来自 pid 文件）+ 按明确的穿透二进制名 + 按命令行含 `server\main.py` / `vite` 的进程
- PowerShell 按命令行过滤可用 `Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*main.py*' }`

### T-D6 · mock provider 自测

**背景**：本环境**未安装** cloudflared / frpc / cpolar，无法实跑真穿透。

**要求**：`mock` provider 让整条链路可离线演练 —— 不起真进程，直接回 `tunnel.mock.url`。

用它做端到端自测并**把过程写进完成报告**：
1. `start-web.ps1 -Tunnel`（配置 provider=mock）→ 应完成 后端就绪 → "穿透" → URL 抓取 → 写 share_url → 打印
2. 检查 `data/config.json` 的 `share_url` 确实被写入
3. `stop-web.ps1` → 后端进程被杀净，`data/.run/*.pid` 清空
4. 重复 `stop-web.ps1` → 幂等不报错
5. 再跑 `start-web.ps1` 前台模式 → 行为与改造前一致（向后兼容回归）
