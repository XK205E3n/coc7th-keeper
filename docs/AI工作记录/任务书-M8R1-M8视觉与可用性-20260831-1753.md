## 5 · 子代理拆分指引

### 5.1 何时用子代理

- ✅ 文件清单 ≥3 个互不重叠的同类任务（如 T-A3 的 4 个 view）
- ✅ 单纯重复（如空状态组件化：新建 1 + 替换 5）
- ❌ 修改同一文件 ≥2 个子代理 → 必合并
- ❌ 涉及 store/router/全局 CSS → 主模型自己改

### 5.2 子代理 prompt 模板

```
任务：T-X1 <任务名>
背景：跑团 Web 平台，前端 Vue3 + Naive UI，位于 D:/DeepSeek Harness/跑团
约束：
- 只许修改以下文件：[白名单]
- 不许引入新依赖
- 不许改 store / API / 路由
- 不许 git 提交
当前状态：[附相关截图与原代码片段]
要求：
- 完成后返回修改清单（每文件 + 行号 + 改了什么）
- 不需要截图，由主模型 modlens 验证
- 不返回成功断言，只返回事实
报告 ≤200 字
```

### 5.3 典型并行配置

```
主模型（modlens）        ─ 监督 + 视觉验收
├─ 子代理 #1 (T-A1)     ─ 全局断点 CSS

```

### B.1 · 顶栏 active 双高亮

- **症状**：`/`、`/play/{key}`、`/characters`、`/content`、`/admin` 任意路径下「总览」与「游玩」同时高亮
- **根因**：`App.vue:118-122` 用 Vue Router 4 默认的 `.router-link-active` 类
- **机制**：`to: '/'` 是所有路径的祖先（Vue Router 4 的 `active-class` 是祖先匹配而非精确匹配）
- **修复方向**（任选其一）：
  - `App.vue:51-58` 用 `RouterLink` 的 `active-class` 改为精确匹配版（如 `:class="{ 'is-active': isActive(item.to) }"` + 自定义 `isActive(item: string)` 函数，规则：item === '/' 时 `route.path === '/'`，否则 `route.path.startsWith(item)`）
  - 或保留 RouterLink，但增加 `exact: true`（Vue Router 4 用 `:to` 对象形式 `to: { path: item.to, exact: true }` 仅对 `/` 起作用）
- **验收脚本**（可在 shot.mjs 注入 eval 验证）：
  ```js
  () => {
    const links = [...document.querySelectorAll('.app-nav-link')].map(a => ({
      label: a.textContent.trim(),
      active: a.classList.contains('router-link-active'),
    }));
    return JSON.stringify(links);
  }
  ```
  期望：每条 path 恰好 1 个 active。
