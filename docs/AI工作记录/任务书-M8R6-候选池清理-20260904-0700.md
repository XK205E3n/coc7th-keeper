## 1. 任务清单（按执行顺序）

### T-E8 · 垃圾房间防护（E3n 已确认，候选池第一）

- `POST /api/games`（`server/api/games.py:130` `create_game`）目前无任何频控。
- 实现**单 IP 建房频控**：滑动窗口内存计数（如 5 个/小时），超限返回 429 + 可读中文提示。
- IP 取值：请求来自回环（穿透场景 cloudflared 回源 127.0.0.1）时取 `X-Forwarded-For` 首段；否则用 `request.client.host`（直连无法伪装）。理由写入完成报告。
- 已通过进站门禁（`access_password` cookie 校验通过）的请求**豁免**频控——门禁本身已是信任边界，避免 E3n 自己开团被拦。
- 现有 96 项测试大量建房，**不得被频控打破**：在 `server/tests/conftest.py` 加 autouse 夹具每例重置计数器（生产路径不受影响）。
- 新增 pytest：同 IP 第 6 间 429、不同 IP 不受影响、门禁豁免、XFF 首段生效。

### T-B1 · 建卡 API 服务端 schema 校验（评估 §1 方案 A）

- `server/api/games.py:90-94` `CharacterBody.character` 从裸 `dict` 改为 Pydantic `CharacterCreate` 模型：校验 `schema` 字面量、`attributes`/`skills` 为 int 取值范围、列表/字典类型。
- **宽松策略（硬约束）**：`state`/`derived`/`sanity`/`meta`/`notes`/`inventory` 可选，缺失由服务端补默认值（`state` 默认形状照抄 `build_character` 产物的字段集，只读取证，不改 engine）。评估已实测 9 张预置卡全部缺 `state`、手动路径缺更多——设必填即破坏现有流程。
- 校验失败走 Pydantic 默认 **422**（评估 §1.3 结论；前端 `catch` 对 400/422 处理一致）。
- `action=auto` 分支不经此校验，行为不变。
- 新增 pytest：直打 API 写非法卡 422、预置卡 JSON 通过、手动最小卡通过且服务端补全 `state`。
