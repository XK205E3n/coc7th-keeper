## 1. T-E8 · 垃圾房间防护

**实现**（`server/api/games.py`）：`create_game` 入口新增 `_enforce_create_rate` —— 模块级滑动窗口（`CREATE_RATE_LIMIT=5` / `CREATE_RATE_WINDOW=3600s`，`threading.Lock` 保护，`create_game` 为 sync 端点跑线程池）。超限 429，提示「建房过于频繁：同一地址每小时最多创建 5 个房间，请稍后再试」。

**三个设计决策**：
1. **IP 取值**（`_client_ip`）：仅回环来源（127.0.0.1/::1/localhost，穿透回源）信任 `X-Forwarded-For` 首段；非回环直连取 `socket` 地址，无法用伪造 XFF 绕过。TestClient 的 `host=testclient` 与回环同置「本地连接」信任位（有注释声明），否则测试无法模拟穿透路径。
2. **门禁豁免**（`_is_gate_authorized`）：已持有效 `access_ok` cookie 的请求豁免——公网场景下门禁本身已是信任边界，避免 E3n 开团被自己拦。cookie 推导与 `main.py` 门禁**同源重复**（`sha256("kp-access:"+pwd)[:24]` 一行，两处注释互指）；未设密码时无人豁免（开放站=最高风险，全员受限）。
3. **既有测试零破坏**：`server/tests/conftest.py` 的 autouse 夹具 `isolated_env` 增加每例 `reset_create_rate()`（上限 5 次/例；扫描确认现存单测试最多建房 4 次）。日志只记「已拦截一个建房请求」，**不落 IP 明细**（M6.5 脱敏约定）。

**用例**（`server/tests/test_m8r6.py`）：第 6 间 429 且提示含频控语义 / 跨 IP 分桶互不影响 / XFF 多级链按首段计数 / 门禁认证后连建 7 间全过。

## 3. T-B1 · 建卡 API 服务端 schema 校验

**实现**：`CharacterBody.character` 从裸 `dict` 改为 `CharacterCreate`（`server/api/games.py`）。

- 校验面：`schema` 字面量 `coc7-character/v1`；`attributes`/`skills` 必须 `dict[str, int]`，取值 0–100 / 0–99（实测 9 卡最大属性 80、最大技能 90，边界不误伤）；`meta/derived/state/sanity` 必须 dict 形状。失败走 FastAPI 默认 **422**（评估 §1.3 结论；前端 `catch` 对 400/422 处理一致）。
- **宽松策略落地**：`extra="allow"` 保留未知字段（防重序列化静默丢数据）；`state`/`sanity` 缺失时按模板形状补默认，数值优先取 `derived.HP/SAN`（无则 10/50，与 pipeline.py 的回退常量一致，零行为漂移）。
- **对任务书的偏离说明**：任务书写「state 默认形状照抄 build_character 产物字段集」——实际 `build_character` 产物**没有 state 字段**（auto 卡本就不带）；实际形状取自评估 §1.4 给出的模板 state 形状，已回写核对。另：`derived`/`meta`/`notes`/`inventory` 缺失**不补**——服务端消费点（`pipeline.py:39-49`、`prompts.py:39-42`）对该四者全 `.get` 防御回退，强行补无收益。
- 附带效果：9 张预置卡建卡后现在会带上补全的 `state`，前端「当前状态」区从无变为有显示（数值与 derived 一致），属改善而非回归。

**用例**：非法卡 4 类各 422（schema 错 / 属性非 int / 属性越界 / 技能越界）；最小手动卡通过且 `state`/`sanity` 补全；真实预置卡（缺 state）通过且数值来自 derived；未知字段保留；`action=auto` 分支不受影响。

## 5. T-F2 · live-SSE 测试基建

**根因确认**：仓库此前**没有任何依赖清单**——重建 venv 会装到"当时最新"，旧版 starlette 把 `/api` 请求喂给 SPA 静态挂载（交接文档记载 86/5 现象的成因）。当前 `.venv` 为已验证良好组合（starlette 1.6.0 + uvicorn 0.52.4，104 passed）。

**修复**：新增 `requirements.txt`，`pip freeze --all` 全量锁定 34 项（含传递依赖——starlette 即 fastapi 的传递依赖，只钉直接依赖防不住漂移）。文件头注明验证环境（CPython 3.14.7）、重锁约定与已知不良组合。

**验证**：`pip install --dry-run --no-index -r requirements.txt` → **34/34 already satisfied、零报错**（离线干跑，不装不重建）。重建 venv 后按清单安装即可复现绿色门禁。

**范围外遗留**：`Dockerfile` 的内联 `pip install fastapi …` 仍为裸装（同样有漂移风险）——接线 requirements.txt 需要同步加 `COPY requirements.txt`，超出本轮允许文件清单，留后续轮。

## 6. T-F3 · Linux start-web.sh / stop-web.sh

按两份 ps1 逐段移植：四模式（前台/`--dev`/`--daemon`/`--tunnel`）+ `--provider`/`--force`；四 provider 分支与 ps1 一致（cloudflared 的 tunnel_name、frp 配置存在性检查、cpolar 本地 4040 API 优先、mock 直返）；URL 抓取轮询 stdout+stderr 双日志并剥 ANSI（60s）；`share_url` 经 `tools/config_cli.py set-share-url` 回写；`access_password` 未设时交互确认；stop 侧 pid 树杀 + 命令行兜底（vite 额外校验项目根路径）+ 幂等。

**与 ps1 的实现差异**（Linux 惯用法）：后台进程经 `setsid` 独立进程组，`kill -- -PID` 整树杀（替代 `taskkill /T`）；依赖探测用 venv 内 python 的 urllib（不引入 curl 依赖）；config 读取仍走 `tools/config_cli.py`（不另写解析）；`--dev` 模式以 `trap EXIT` 回收后端。`start-web.sh` 首次部署提示改为 `pip install -r requirements.txt`。
