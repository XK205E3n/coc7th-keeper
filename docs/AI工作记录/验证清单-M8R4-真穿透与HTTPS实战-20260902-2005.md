# 验证清单 M8R4 · 真穿透与异地 HTTPS 实战

> **执行人**：E3n（本机 Windows 原生环境）
> **为什么必须本机跑**：开发沙箱禁止 `Start-Process` 后台拉起进程，M8R4 的两个后台模式（`-Daemon` / `-Tunnel`）在沙箱内**无法端到端实跑**。本机不受此限。
> **目标**：验证 P0 修复有效 + 完成挂了三个里程碑的 **T-C2 异地 HTTPS 实战**（原本因"需公网+域名"一直标 ⏳，穿透整合后首次可做）。
> **通过后**：发 v1.0.3 Release。
> **结果记录**：文末有表格，跑一项填一项；失败项按「取证路径」留日志，交回 Kern 判断。

---

## 0. 前置准备

### 0.1 安装 cloudflared

```powershell
winget install Cloudflare.cloudflared
```

装完**重开一个 PowerShell 窗口**（PATH 需要刷新），验证：

```powershell
cloudflared --version
# PASS 判据：输出 cloudflared version 2026.x.x，不是「不是内部或外部命令」
```

### 0.2 环境预检

```powershell
cd "D:\DeepSeek Harness\跑团"

# 端口 18000 必须空闲，否则后端起不来
netstat -ano | findstr :18000
# PASS 判据：无输出。有输出则先 .\stop-web.ps1 或 taskkill /PID <末列> /T /F

# 前端产物存在（否则 -Tunnel 会触发 npm build）
Test-Path frontend\dist\index.html     # PASS：True

# 目录状态
Get-ChildItem data\.run -ErrorAction SilentlyContinue
# 首次应为空或不存在
```

### 0.3 设置访问密码（重要）

穿透即公网暴露。先设密码，可跳过脚本的安全确认：

```json
// data/config.json
"access_password": "你自定义的密码"
```

不设也行 —— 脚本会红字警告并要求确认，加 `-Force` 可跳过。**但真穿透验证建议设上**，正好顺带验证密码功能。

## 1. 验证 A · 后台模式 `-Daemon`（P0 修复的核心验证）

这一项直接验证被修复的 P0。修复前必崩（`InvalidOperationException: ...are same`）。

```powershell
.\start-web.ps1 -Daemon
```

**PASS 判据**（三条全满足）：
1. 打印 `[后端] 已后台启动 PID <n>`，**脚本随即退出回到命令行**（不是阻塞）
2. `curl http://localhost:18000/api/health` → `{"status":"ok"}`
3. `Get-ChildItem data\.run` 出现 `backend.pid`、`backend.log`，且 `backend.log` 有内容（非 0 字节）

```powershell
curl http://localhost:18000/api/health
Get-ChildItem data\.run
Get-Content data\.run\backend.log -Tail 5
```

**失败取证**：
- 若报 `RedirectStandardOutput ... are same` → P0 未修好，把完整报错发回
- 若 30s 未就绪 → 看 `data\.run\backend.log`

.\stop-web.ps1     # 再执行一次

**PASS 判据**：打印「无运行中进程」，**不报错**（幂等）。

```powershell
Get-Process python -ErrorAction SilentlyContinue | Where-Object { $_.Path -like "*跑团*" }
# PASS：无输出（无残留后端进程）
```

## 4. 验证 D · 真穿透（cloudflared）—— 本轮核心

```powershell
.\start-web.ps1 -Tunnel
```

**PASS 判据**（关键在 #1）：
1. **抓到公网地址** `https://<随机>.trycloudflare.com` —— 这条验证的是「URL 打在 stderr、脚本从 `tunnel.log.err` 抓到」这条修复后的路径
2. `data/config.json` 的 `share_url` = 该地址
3. 本地访问 `http://localhost:18000` 正常

```powershell
curl https://<你的地址>.trycloudflare.com/api/health
# PASS：返回 {"status":"ok"}
```

**超时判定**：脚本轮询 60s。正常情况 5–20s 出地址。若 60s 超时：

```powershell
Get-Content data\.run\tunnel.log -Tail 20
Get-Content data\.run\tunnel.log.err -Tail 20     # ← URL 多半在这
```

**最可能的失败**：国内网络访问 `trycloudflare.com` 慢或不通。
- 判据：日志里有 URL，但 `curl` 超时
- 替代：换 cpolar（`winget` 未必有，去 cpolar.com 下载），配置 `tunnel.provider = "cpolar"` 后重跑
- 若换 provider，请顺带帮我确认 cpolar 的 `http://127.0.0.1:4040/api/tunnels` 返回结构 —— 这是 Hy3 标注为「未确认」的部分

## 5. 验证 E · 异地 HTTPS 实战（T-C2，挂了三个里程碑）

这是整份清单里**唯一能证明整条链路真的通**的测试。

**步骤**：
1. 保持验证 D 的穿透运行，记下公网地址
2. **用手机**（关掉 Wi-Fi 走蜂窝网络，确保不在同一内网）或让朋友访问：
   ```
   https://<你的地址>.trycloudflare.com
   ```
3. 完整走一遍：进首页 → 输入访问密码 → 建房/加入 → 建卡 → 掷骰 → 看 AI 叙事

**PASS 判据**：
| 项 | 判定 |
|----|------|
| 页面加载 | 手机上看得到完整前端（不是 404 / 空白） |
| HTTPS | 地址栏是锁头，无证书警告 |
| 密码 | 输入密码能进（若设了 access_password） |
| 建卡 | 能选预置卡或粘贴 JSON |
| 掷骰 | 能掷出骰果，服务端返回结果 |
| AI 叙事 | 能推进一轮，拿得到 AI 回复（需 secrets.json 里有 API Key） |
| SSE 实时 | 房间内另一人掷骰，本机能实时看到（不刷新） |

**失败取证**：`data\.run\backend.log` + 手机端截图。

> 这一项如果过了，CHANGELOG 里「异地 HTTPS 实战 ⏳」可以翻成 ✅ —— 它是 v1.0 发布时留下的唯一硬阻塞。
