# 部署指南（M6.4）· 三档方案

> 对照计划书 §6「多人联机部署方案对比」。本平台纯 Web，部署只差"用什么地址访问 + 是否 HTTPS"，
> 代码零改动（邀请链接由前端按当前地址或 `VITE_SHARE_URL` 生成，见 §5）。

## 0. 三档对比速览

| 维度 | 本地局域网 | 公网（内网穿透） | 公网（云服务器） |
|---|---|---|---|
| 成本 | 0 | 免费额度（SakuraFrp / Cloudflare Tunnel / Tailscale Funnel） | 云主机月费（轻量级即可） |
| 安全 | 局域网内 | 建议设访问密码 + 尽量 HTTPS | 可配 HTTPS + 密码 + 限流 |
| 实现 | 零配置，直接访问 `http://<本机IP>:18000` | 隧道工具指向 18000 | 域名 + Nginx/Caddy 反代 + HTTPS |
| 适用 | 同 Wi-Fi/宿舍 | 临时开团、异地朋友 | 稳定长期对外 |

---

## 1. 准备（三种方案通用）

```bash
# 装依赖（首次）
python -m venv .venv
.venv\Scripts\python -m pip install fastapi "uvicorn[standard]" openai httpx
# 构建前端静态产物（后端会直接托管 dist/，无需单独开 vite）
cd frontend && npm install && npm run build && cd ..
# 一键启动（等效上面两步 + 运行）
.\start-web.ps1          # 或 start-web.bat
```

启动后浏览器访问 `http://localhost:18000`：前端页面由后端静态挂载，`/api` 同源直连。

> 配置模型（可选）：`data/config.json` 填 `model.base_url/model`，`data/secrets.json` 填 `api_key`
> （DeepSeek / Ollama / 硅基流动均兼容）；不配则守密人走离线兜底（规则判定 + 模板叙事）。
> 开发者监视（可选）：`data/config.json` 设 `"dev_token": "..."` 后，"管理"页可只读查看房间内部。

## 2. 本地局域网

1. 启动后确认监听地址：默认 `127.0.0.1:18000`（仅本机）。要开放给局域网，把 `data/config.json`
   的 `server.host` 改为 `0.0.0.0`（或 `start-web` 前设环境变量），重启。
2. 查本机局域网 IP：`ipconfig`（如 `192.168.1.20`）。
3. 同伴浏览器访问 `http://192.168.1.20:18000`。
4. **防火墙放行**：Windows 弹窗选"允许"；或手动 `netsh advfirewall firewall add rule name="COC Web 18000" dir=in action=allow protocol=TCP localport=18000`。
5. 风险提示：局域网内**无加密**，建议建房时设访问密码（创建冒险填"访问密码"）；仅同 Wi-Fi 小范围使用。
6. 邀请链接：房主面板复制后自动使用 `http://192.168.1.20:18000/?key=...&invite=...`（前端按实际访问地址生成）。

## 3. 公网：内网穿透（SakuraFrp / Cloudflare Tunnel）

> 原理：把本机 18000 端口通过隧道暴露到公网，拿一个公网 https 地址分发给朋友。

### 3.1 SakuraFrp（国内直连快，需注册）

1. 官网注册 → 创建隧道：本地 IP `127.0.0.1`，本地端口 `18000`，类型 HTTP。
2. 下载并运行 launcher（或命令行客户端），登录后隧道自动上线。
3. 隧道详情里的**访问地址**（`https://xxxx.frp...` 或 `http://`）发给朋友。
4. 若平台给的是 http 而非 https，可配合域名+HTTPS（见 §4）；至少设访问密码。

### 3.2 Cloudflare Tunnel（全球 CDN + 免费 https，无需公网 IP）

1. 安装 `cloudflared`（[cloudflare.com/cloudflared](https://developers.cloudflare.com/cloudflared/)）。
2. 一条命令（临时隧道，无需域名）：
   ```bash
   cloudflared tunnel --url http://localhost:18000
   ```
   它会打印一个 `https://random-name.trycloudflare.com` 地址，直接分给朋友即可。
3. 需要固定域名：`cloudflared tunnel login` → `cloudflared tunnel create coc` →
   配置 `~/.cloudflared/config.yml` 指向 18000 → `cloudflared tunnel run coc`。
4. **重要**：外网访问时必须设访问密码（M6.1）——公网人人可扫，不设密码等于开门。

> 外网化邀请链接：前端已支持 `VITE_SHARE_URL`。若前端页面也是经隧道访问，链接自动正确；
> 若前端与后端域名不同，构建前端时设环境变量：`VITE_SHARE_URL=https://你的域名 npm run build`。

### 3.3 localtunnel（免安装免注册，临时测试最快）

> 无需下载客户端、无需注册，Node 环境一条命令即可（本机已有 Node 22+）。

```bash
npx localtunnel --port 18000
```

- 输出 `https://<随机名>.loca.lt`，直接分给朋友即可（HTTPS 免费）。
- 首次访问会有一个"输入公网 IP 确认"的中间页（输入 `tunnel.localhost` 或你的公网 IP 即可进入）。
- 适合**临时联机测试**；地址每次重启都会变，不适合长期开团。

### 3.4 隧道地址易变怎么办

| 场景 | 方案 |
|---|---|
| 临时测试（几分钟~几小时） | Cloudflare 临时隧道 / localtunnel，地址变了重新复制即可 |
| 长期开团（固定地址） | SakuraFrp 免费隧道（地址相对稳定）或 Cloudflare 命名隧道 + 自有域名（`cloudflared tunnel create`） |
| 邀请链接跟随地址 | 前端按**浏览器当前地址**生成邀请链接，玩家从哪个地址进就发哪个地址，无需额外配置 |

## 4. 公网：云服务器（域名 + 反代 + HTTPS）

1. 云主机放行 18000（安全组 + 防火墙），或只放行 80/443 由反代转发（推荐，见 HTTPS 文档）。
2. 上传代码，`pip install` + `npm run build`，`python server/main.py`（systemd 可用，示例见 §6）。
3. 域名 A 记录指向云主机 IP。
4. **HTTPS 反代**：Caddy（自动证书，一行配置）或 Nginx + certbot，见 `docs/部署/HTTPS反代.md`。
5. 设访问密码 + 建议开 `dev_token` 供自查。
6. 邀请链接自动使用 `https://你的域名/...`（前端按访问地址生成）。

## 5. 邀请链接外网化（M6.1 share_url）

- 大多数场景无需配置：邀请链接由**浏览器当前地址** + `?key=&invite=` 参数生成，玩家在哪访问就发哪个地址。
- 需要固定公网地址（如隧道地址会变、前端与后端分离）时：
  - 前端构建时：`VITE_SHARE_URL=<公网地址> npm run build`，此后邀请链接固定用该地址。
  - `data/config.json` 的 `share_url` 保留为后端侧配置占位（未来管理页展示用）。

## 6. 生产运行（云服务器）建议

- 用 systemd 守护：
  ```ini
  [Unit]
  Description=CoC Web Platform
  After=network.target
  [Service]
  WorkingDirectory=/opt/coc-web
  ExecStart=/opt/coc-web/.venv/bin/python server/main.py
  Restart=always
  [Install]
  WantedBy=multi-user.target
  ```
- 或 Docker（单容器，见 `Dockerfile`）：
  ```bash
  docker build -t coc-web .
  docker run -d --name coc-web -p 18000:18000 -v coc-web-data:/app/data coc-web
  ```

## 7. 排错步骤（FAQ）

| 症状 | 排查 |
|---|---|
| 本机能开、局域网打不开 | ① `config.json` 的 `server.host` 是否为 `0.0.0.0`；② 防火墙是否放行 18000；③ 同伴是否同网段 |
| 公网隧道开了但打不开 | ① 隧道本地端口是否 `18000`；② 隧道类型是否 HTTP/HTTPS 而非 TCP 直连；③ 本机是否还开着 vite（5173）干扰 |
| localtunnel 打开是"确认页" | 首次访问输入 `tunnel.localhost` 或你的公网 IP 确认；或让朋友直接访问（确认页只拦本机） |
| 打开页面但 `/api` 403/404 | 反代是否把 `/api` 一并转发（Nginx 不要只转 `/`）；后端是否在 18000 正常 |
| 页面能开、SSE 断连 | 反代需开启 SSE 透传：Nginx 关闭代理缓冲 / Caddy 默认即支持（见 HTTPS 文档）；别给 `/api/games/*/events` 强加超时 |
| 邀请链接打不开 | 确认邀请码没有空格/被截断；房主已轮换过码则旧链接失效，重新复制 |
| Docker 起不来 | `docker logs coc-web` 看依赖是否装齐；`/app/data` 卷权限（`chmod 777` 或挂子目录） |
| 中文路径奇怪 | 本项目根目录含中文属正常；Linux/云主机部署时路径一致即可；vite 构建在 Windows 上已验证 |
