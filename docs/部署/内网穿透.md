# 内网穿透（一键暴露公网 · M8R4）

> 把本机 `18000` 端口通过隧道暴露到公网，拿一个 https 地址分发给朋友联机。
> 本文取代 [`部署指南.md` §3](部署指南.md) 的手工命令版，并把穿透做成项目一等公民：
> **配置化**（`data/config.json` 的 `tunnel` 段）+ **脚本化**（`start-web.ps1 -Tunnel` / `stop-web.ps1`）+ **一键关闭**。

---

## 0. 一键方式（推荐）

```bash
# 1) 启动并穿透（默认 provider=cloudflared；可用 -Provider 切换）
.\start-web.ps1 -Tunnel
#   或显式指定：
.\start-web.ps1 -Tunnel -Provider cloudflared
.\start-web.ps1 -Tunnel -Provider frp
.\start-web.ps1 -Tunnel -Provider cpolar
.\start-web.ps1 -Tunnel -Provider mock      # 自测：不启真进程，直接回 mock 地址

# 2) 关闭（树杀后端 + 穿透，清 pid 文件，日志保留）
.\stop-web.ps1

# 3) 状态查询
.\status-web.ps1
```

`-Tunnel` 做了什么（严格顺序，任一步失败即清理已起进程并退出）：

1. 检查 `.venv` 与前端产物 `frontend/dist/index.html`（缺失则自动构建）
2. **安全检查**：`access_password` 为空时红色警告并要求确认（非交互环境视为拒绝）；加 `-Force` 跳过
3. 后台起后端（隐藏窗口），轮询 `GET /api/health` 等就绪（超时 30s）
4. 起穿透进程（stdout+stderr 重定向到 `data/.run/tunnel.log`）
5. 抓公网 URL（cloudflared 从 stderr 正则提取；cpolar 优先读本地 `4040/api/tunnels`），超时 60s
6. 写回 `data/config.json` 的 `share_url` 并 `save_config()`（保留你已有配置，只改该字段）
7. 打印汇总：本地地址 / 公网地址 / PID / 关闭命令

输出示例（mock provider）：

```
[后端] 就绪 PID 6860
[穿透] mock provider（自测模式，不启真进程）→ https://mock-abcdef.trycloudflare.com
========== 穿透已建立 ==========
本地地址 ：http://localhost:18000
公网地址 ：https://mock-abcdef.trycloudflare.com
后端 PID ：6860  (mock 无进程)
分享地址已写入 data/config.json 的 share_url
关闭命令 ：.\stop-web.ps1
================================
```

`-Tunnel` 与 `-Dev` 互斥（同时传直接报错退出）。

## 1. 三种 provider 选型对比

| 维度 | cloudflared（Cloudflare Tunnel） | frp（自建 frps） | cpolar（国产 SaaS） |
|---|---|---|---|
| 是否需公网服务器 | 否 | **是**（需一台有公网 IP 的 frps） | 否 |
| 是否免费 | 免费（临时隧道） | frps 服务器自己承担 | 有免费额度，长期/带宽收费 |
| 地址是否固定 | 临时隧道每次变；命名隧道+自有域名可固定 | 取决于 subdomain/域名，**可固定** | 免费隧道常变；付费可固定 |
| 国内访问速度 | 全球 CDN，但国内有时不稳定 | 取决于 frps 位置，可控 | **国内快** |
| 是否需自有域名 | 命名隧道需要 | subdomain 用 frps 域名；customDomains 需自有域名 | 不需要（或用其域名） |
| 上手难度 | 最低（一条命令） | 中（要搭 frps） | 低（注册即用） |
| 备注 | 本项目默认 provider；URL 打在 stderr | 需 `tools/frpc.toml` 模板 | URL 抓取优先本地 API `4040/api/tunnels` |

> 临时开团首选 **cloudflared**；国内朋友多、要稳定 → **cpolar** 或自建 **frp**；长期固定地址 → frp/cpolar 付费或 Cloudflare 命名隧道+域名。

## 2. 安装与首次配置

### 2.1 cloudflared

```bash
# Windows（任选其一）
winget install cloudflared
# 或 https://developers.cloudflare.com/cloudflared/ 下载
```
临时隧道零配置：`start-web.ps1 -Tunnel` 自动执行 `cloudflared tunnel --url http://127.0.0.1:18000`，
打印 `https://<随机>.trycloudflare.com`。固定域名需 `cloudflared tunnel login` + `create` + 配置（不在本脚本范围）。

### 2.2 frp

1. 准备一台有公网 IP 的服务器，装 `frps` 并跑起来（参考 https://gofrp.org ）。
2. 复制模板：把 `tools/frpc.toml` 填好 `serverAddr` / `auth.token`，并二选一填 `subdomain` 或 `customDomains`。
3. `start-web.ps1 -Tunnel -Provider frp` 读取 `tools/frpc.toml` 启动 `frpc`。
   > 注意：`frpc.toml` 含 `auth.token`，请勿把真实值提交仓库。

### 2.3 cpolar

```bash
# https://www.cpolar.com 下载安装，或
# scoop install cpolar
```
`start-web.ps1 -Tunnel -Provider cpolar` 执行 `cpolar http 18000`。
URL 抓取优先读本地 `http://127.0.0.1:4040/api/tunnels`（ngrok 风格 API），读不到再解析日志。
（cpolar 的本地 API 结构与返回字段本项目**未实跑确认**，见 §4 限制。）

### 2.4 mock（自测逃生舱）

不启任何真进程，直接返回 `tunnel.mock.url`（`server/config.py` 默认值
`https://mock-abcdef.trycloudflare.com`）。用于离线演练全链路（后端就绪→URL 抓取→写 share_url→关闭），
无需安装任何穿透二进制。

## 3. 手工方式（保留，供自建 frp / 特殊场景）

### 3.1 Cloudflare Tunnel（手工）

```bash
cloudflared tunnel --url http://localhost:18000
# 或命名隧道：cloudflared tunnel create coc → 配置 → cloudflared tunnel run coc
```

### 3.2 SakuraFrp（国内直连快）

注册 <https://www.natfrp.com/> → 创建隧道（TCP/HTTP，本地端口 18000）→ 启动客户端 → 用分配地址分享。

### 3.3 localtunnel（免安装免注册）

```bash
npx localtunnel --port 18000
```
输出 `https://<随机>.loca.lt`，适合临时联机测试；首次访问有确认页。

### 3.4 frp（手工）

```bash
frpc -c tools/frpc.toml
```

## 4. 已知限制（本仓库环境）

- **cloudflared / frp / cpolar 的实跑未在本机验证**：开发机未安装这三个二进制，`-Tunnel` 走真 provider
  时会在「二进制缺失」处明确报错并打印官方安装指引（**不静默跳过**）。已用 `mock` provider 跑通全链路逻辑。
- **cpolar 的 URL 抓取**：优先本地 API `4040/api/tunnels`、回退解析日志；该 API 返回结构**未实跑确认**，
  若与预期不符，抓不到地址会 60s 超时并关闭穿透（可在 `data/.run/tunnel.log` 排查）。
- **frp 的 URL 自动拼装**：需 `tools/frpc.toml` 的 `subdomain`/`customDomains` + frps 域名才能拼出完整公网地址；
  若拼不出则回退抓日志中的 http(s) URL（best-effort，未实跑）。

## 5. 安全须知（穿透即公网暴露）

1. **必设访问密码**：穿透后公网任何人可进你的房间。开局前在 `data/config.json` 设 `access_password`，
   或在 `start-web.ps1 -Tunnel` 的警告里确认继续（建议先用 `-Force` 仅用于受信网络自测）。
2. **`dev_token` 不要外泄**：管理页只读监视用的 token，公网暴露时切勿设置弱随机值。
3. **限流建议**：`rate_limit` 默认每 IP 每分钟 300、突发 20；公网开放可适当调低 `per_minute`。
4. **日志脱敏**：`data/.run/*.log` 含运行日志，关闭后保留便于排查，但勿外发（可能含 IP/路径）。
5. **关服即撤隧道**：`stop-web.ps1` 会树杀穿透进程；长期不用请确认进程已清（`.\status-web.ps1` 可查）。
