# 模组拆解说明（Module Pack Format v2）

> 版本：v0.1（草案，随 MILESTONES.md 一并审核）｜ 日期：2026-08-31
> 用途：把 **PDF / 文本+图片混合** 的模组源材料，拆解为项目可读取的结构化模组包，供 AI 守密人按需读取。
> 参考：`archive/coc7th-keeper-feishu/.dsh/skills/coc7th-keeper/modules/toy-dancer-comes/`（coc7-module/v1 拆解方式），本格式为其升级版。

---

## 1. 设计目标

1. **AI 可读**：模组内容按"开局注入 / 场景注入 / 按需检索"三种模式组织，AI 守密人不需要通读全文就能正确调度。
2. **隐私分级**：PL 视角内容（`plot.md`）与守密人真相（`kp-notes.md`）物理分离，玩家视图永不接触后者。
3. **图片可管理**：PDF 里的插图 / 地图 / 立绘拆出为 `handouts/` 分类图片，声明"何时展示、给谁看"。
4. **可校验**：拆解产物有明确 schema 与校验清单，AI 或人工都能检查完整性。

## 2. 目录结构

```
modules/<module_id>/
├── meta.json          # 元数据（schema: trpg-module/v1）
├── plot.md            # PL 视角剧本（背景 / 开场 / 场景 / 检定 / 结局）
├── kp-notes.md        # 守密人真相（只进 AI 上下文，绝不进玩家视图）
├── clues.md           # 线索表（编号 / 触发条件 / 内容 / 私密标记）
├── npcs.json          # NPC（公开字段 + 隐藏字段）
├── monsters.json      # 怪物（公开字段 + 隐藏字段）
├── scenes.json        # ★ 场景结构化（场景 ID / 描述 / 检定 / 线索 / NPC / 附件引用 / 顺序）
├── pregens/           # 预制角色（JSON，schema 同角色卡）
├── handouts/          # 图片附件（按用途分类，见 §4.7）
└── README.md          # 可选：来源 / 授权条款 / 拆解备注
```

## 3. 文件规范

### 3.1 `meta.json`（schema: `trpg-module/v1`）

```json
{
  "schema": "trpg-module/v1",
  "id": "toy-dancer-comes",
  "number": 2,
  "name": "Toy Dancer Comes",
  "cn": "玩具跳着舞蹈来",
  "author": "Yukishiro",
  "language": "zh-CN",
  "system": "coc7",                    // 本期仅 coc7；dnd5e 后续
  "players": "1",
  "duration": "3-4 小时",
  "recommended_skills": ["侦查", "图书馆使用", "战斗类技能"],
  "tags": ["克苏鲁神话", "日系恐怖", "单 PL 友好"],
  "summary": "……",
  "background": {"year": "2012", "location": "松寒市 秋林苑 7 号楼"},
  "source": {                          // ★ 源材料信息（拆解溯源）
    "type": "pdf",                     // pdf | text | text_image_mixed
    "file": "玩具跳着舞蹈来.pdf",
    "pages": 42,
    "notes": "原版 PDF 存放于 archive/模组/，不入库"
  },
  "scene_flow": ["s01", "s02", "s03"], // ★ 场景顺序（对应 scenes.json 的 id）
  "files": {
    "plot": "plot.md",
    "kp_notes": "kp-notes.md",
    "clues": "clues.md",
    "npcs": "npcs.json",
    "monsters": "monsters.json",
    "scenes": "scenes.json",
    "pregens": "pregens/",
    "handouts": "handouts/"
  }
}
```

### 3.2 `plot.md`（PL 视角剧本）

沿用 toy-dancer-comes 的写法：背景 → 开场（守密人朗读）→ 关键场景表 → 各场景细节 → 结局。**只含玩家可看内容**；守密人调度提示用 `> 🔒 守密人：` 引用块标注（AI 读取时识别，不输出给玩家）。

### 3.3 `kp-notes.md`（守密人真相）

只进 AI 上下文。含：真相、NPC 隐藏动机、未揭示线索、失败后果预案。**任何情况下不进入玩家视图**（服务端过滤层保证）。

### 3.4 `clues.md`（线索表）

```markdown
## C01 · 符文在呼吸
- 触发：侦查成功（困难）检查一楼展示柜
- 私密：是（只给发现者）
- 内容：你注意到墙上的符文在缓慢地呼吸……
- 关联：场景 s02 / NPC 沈珂成
```

### 3.5 `npcs.json` / `monsters.json`

```json
{
  "id": "shen-kecheng",
  "name": "沈珂成",
  "public": {"appearance": "俊朗年轻人，挽起袖子", "behavior": "热情好客", "lines": ["等你很久了。"]},
  "hidden": {"true_identity": "谢尔顿的伪装", "stats": {"str": 60, "con": 70}}
}
```

- `public` → 玩家视图 / 叙事可用；`hidden` → 只进 AI 上下文与开发者监视接口。

### 3.6 `scenes.json`（★ 新增：场景结构化）

```json
{
  "scenes": [
    {
      "id": "s01",
      "name": "抵达园区",
      "location": "秋林苑门口",
      "summary": "出租车驶入，铁艺大门，保安室，原木色别墅",
      "checks": [
        {"kind": "skill", "skill": "知识", "target": 50, "note": "建筑风格"},
        {"kind": "psychology", "note": "观察沈珂成"}
      ],
      "clues": ["C01"],
      "npcs": ["shen-kecheng"],
      "handouts": ["cover.jpeg", "maps/qiulin-park-map.jpeg"],
      "next": ["s02"]
    }
  ]
}
```

**AI 读取模式**：`room.json` 记录 `current_scene`；场景切换时把该场景的 `summary / checks / clues / npcs / handouts` 注入 LLM 上下文，并展示附件给玩家。**不需要 AI 通读全文**。

### 3.7 `handouts/`（图片附件，按用途分类）

```
handouts/
├── cover/        # 封面 / 氛围图
├── portraits/    # 角色立绘（NPC / 玩家）
├── maps/         # 地图（园区 / 楼层 / 区域）
├── items/        # 道具图（信件 / 符咒 / 机关）
└── kp-tips/      # 守密人提示图（只进 AI 上下文，不展示给玩家）
```

每张图在 `scenes.json` 或 `meta.json` 中声明用途（何时展示、给谁看、是否 kp-only）。

## 4. AI 读取模式（三种注入）

| 模式 | 内容 | 时机 |
|---|---|---|
| **开局注入** | `meta.json`（摘要/背景/技能）+ `plot.md` 摘要 + `kp-notes.md` 全文 | 创建游戏 / 开局 |
| **场景注入** | `scenes.json` 当前场景：summary / checks / clues / npcs / handouts | 场景切换时 |
| **按需检索** | `clues.md`（解锁时）、`npcs.json`/`monsters.json`（交互时，public 进玩家视图）、`pregens/`（建卡时） | 运行时按需 |

## 5. 拆解步骤（源材料 → 模组包）

1. **通读源材料**（PDF / 文本+图片），识别：背景、场景流程、检定、线索、NPC、怪物、附件图片。
2. **分文件**：按 §3 规范写入 `plot.md` / `kp-notes.md` / `clues.md` / `npcs.json` / `monsters.json` / `scenes.json`。
3. **图片分类**：从 PDF 提取插图，按用途放入 `handouts/` 分类目录（jpg/png/webp，单张 ≤ 10MB）。
4. **预制角色**：如有，转成角色卡 JSON 放入 `pregens/`。
5. **校验**：跑 §6 校验清单。
6. **登记**：`number` 递增，`/api/modules` 自动收录（扫描 `modules/` 目录）。

## 6. 校验清单

- [ ] `meta.json` 合法 JSON，`schema == "trpg-module/v1"`，必填字段齐全（id/number/cn/system/summary/files）
- [ ] `files` 中声明的每个文件/目录实际存在
- [ ] `plot.md` / `kp-notes.md` / `clues.md` 为 UTF-8 Markdown
- [ ] `npcs.json` / `monsters.json` / `scenes.json` 合法 JSON，`scenes[].id` 与 `meta.scene_flow` 一致
- [ ] `handouts/` 图片格式合法（jpg/png/webp），`scenes.json` 引用的附件存在
- [ ] `kp-notes.md` 与 `plot.md` 无交叉泄漏（真相只出现在 kp-notes）
- [ ] 原版 PDF 等授权材料**不入库**（放 `archive/模组/` 或本地），模组包内只放拆解产物
