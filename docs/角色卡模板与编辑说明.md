# 角色卡模板与编辑说明（Character Sheet Format v1）

> 版本：v1.0 ｜ 日期：2026-09-01
> 用途：统一定义跑团 Web 平台的角色卡 JSON（`coc7-character/v1`）——**玩家用 AI 生成角色卡、或手工编辑时，按本说明产出的 JSON 可直接上传写入**，前端角色页 / 游玩页 / 理智结算 / 状态变动全部正常识别。
> 配套文件：`templates/character-sheet-template.json`（可直接上传的完整模板）
> 相关实现：`server/engine/build.py`（引擎自动生成）、`server/state_apply.py`（状态段维护与校验）、`frontend/src/components/CharacterSheet.vue`（前端展示）

---

## 1. 设计目标

1. **统一模板**：所有角色卡（AI 生成 / 手工填写 / 模组预制）遵守同一 JSON 结构，平台各处的渲染与结算无需特判。
2. **AI 可生成**：玩家把想法（职业、属性倾向、技能侧重）告诉任意 LLM，按 §8 的提示词模板即可得到合规 JSON，**直接粘贴上传**。
3. **零依赖上传**：`POST /api/games/{key}/characters` 直传角色卡 JSON 即写入（无需后端参与计算）；`state` 段可省略，后端自动补齐。
4. **可校验**：本文档给出字段约束与自检清单（§9），上传前即可自查。

> ⚠️ 说明：当前建卡接口**不做 schema 校验**（直传零校验为已知遗留项）。因此模板字段名、类型、取值范围**必须严格按本文档**，否则前端可能出现空白值或状态异常。见 §9 自检清单。

---

## 2. 角色卡 JSON 总览

根对象（schema: `coc7-character/v1`）：

```json
{
  "schema": "coc7-character/v1",
  "name": "角色名",
  "cn": "中文名（可选）",
  "meta": { "age": 25, "occupation": "私家侦探" },
  "attributes": { "STR": 50, "CON": 50, "SIZ": 50, "DEX": 50, "APP": 50, "INT": 50, "POW": 50, "EDU": 60, "LUK": 50 },
  "derived": { "HP": 10, "MP": 10, "SAN": 50, "DB": "0", "MOV": 8 },
  "skills": { "Spot Hidden": 25, "First Aid": 30, "……": "…" },
  "inventory": ["手电筒", "笔记本"],
  "notes": ["背景故事一段"],
  "sanity": { "current": 50, "max": 50, "history": [] },
  "state": { "hp": 10, "max_hp": 10, "san": 50, "max_san": 50, "clues": [], "conditions": [], "gold": 0 }
}
```

字段速查：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schema` | string | ✅ | 固定 `"coc7-character/v1"` |
| `name` | string | ✅ | 角色显示名（玩家名不同名也可） |
| `cn` | string | — | 中文名/别称，角色页头部展示 |
| `meta` | object | — | `age` 年龄、`occupation` 职业（角色页展示） |
| `attributes` | object | ✅ | 九项基础属性（§4.1） |
| `derived` | object | ✅ | 五项派生值（§4.2） |
| `skills` | object | ✅ | 技能表：英文技能名 → 数值（§6） |
| `inventory` | array | — | 物品字符串列表 |
| `notes` | array | — | 角色笔记/背景（仅展示用） |
| `sanity` | object | — | `current`/`max`/`history`（理智历史，后端写入） |
| `state` | object | — | 可变状态（HP/SAN 现值、线索、状态、金钱；可省略，后端自动补齐） |

> `inventory` / `notes` / `sanity` / `state` 均可省略或为空——后端 `ensure_char_state` 会自动补齐 `state` 默认值（§5.2）。

## 3. 模板文件

`templates/character-sheet-template.json` 是一个**可直接上传**的完整角色卡：九属性 50 基准（EDU 60）、派生值按其推算、46 项默认技能（与引擎自动生成一致）。使用方式：

1. 复制模板内容；或把 `POST /api/games/{key}/characters` 的 `character` 字段直接设成该 JSON。
2. 改 `name`（至少）；按需微调属性/技能/物品。
3. 上传（§7）。上传后 `state` 若缺省，后端自动按 `derived.HP` / `sanity.max`/`derived.SAN` 补全。

**派生值要与属性自洽**（否则前端显示与裁决口径不一致）：修改属性后请按 §4.2 重算 `HP / MP / SAN / DB / MOV`。

---

## 4. 属性与派生规则

### 4.1 `attributes`（九项基础属性）

| 键 | 中文 | 取值惯例 |
|---|---|---|
| `STR` | 力量 | 3–99，通常 40–90 |
| `CON` | 体质 | 同上 |
| `SIZ` | 体型 | 同上 |
| `DEX` | 敏捷 | 同上 |
| `APP` | 外貌 | 同上 |
| `INT` | 智力 | 同上 |
| `POW` | 意志 | 同上 |
| `EDU` | 教育 | 同上 |
| `LUK` | 幸运 | 同上 |

> **POW 注意**：本平台（与 CoC7th 规则同）把 POW 直接按百分制刻度存储（如 80），**不是** 3–18 的骰值。`SAN` 的推导以此为准（§4.2）。

### 4.2 `derived`（五项派生值，公式与引擎一致）

| 键 | 公式 | 示例（50/50/50/60） |
|---|---|---|
| `HP` | `ceil((CON + SIZ) / 10)` | 50+50 → 10 |
| `MP` | `ceil(POW / 5)` | 50 → 10 |
| `SAN` | **= POW（百分制，初始理智即意志值，非 POW×5）** | 50 → 50 |
| `DB` | 查表：STR+SIZ ≤64→`"-2"`；≤84→`"-1"`；≤124→`"0"`；≤164→`"+1d4"`；≤204→`"+1d6"`；否则`"+2d6"` | 100 → `"0"` |
| `MOV` | 8；STR < DEX 且 STR < 80 → −1；SIZ > 79 → −1（最低 1） | 8 |

> ⚠️ **SAN 历史教训**：引擎早期曾写 `POW × 5` 导致 SAN=400+（已修复为 `san = pow_`）。**手工/AI 生成时切勿再乘 5**，否则理智检定永远成功、SAN 永不损失。

### 4.3 `sanity` 段

```json
"sanity": { "current": 50, "max": 50, "history": [] }
```

- `current` / `max`：初始相等（= `derived.SAN`）；游戏内理智损失由后端写入 `history`：`{ts, loss, reason, insane_kind}`，前端展示最近 5 条。
- SAN 归 0 → 永久疯狂（`state.conditions` 追加）。

### 4.4 `state` 段（可变状态，可省略）

```json
"state": { "hp": 10, "max_hp": 10, "san": 50, "max_san": 50, "clues": [], "conditions": [], "gold": 0 }
```

- `max_hp` 缺省取 `derived.HP`（再缺省 10）；`max_san` 缺省取 `sanity.max` → `sanity.current` → `derived.SAN`（再缺省 50）。
- `hp` / `san` 会被钳制到 `[0, max]`。
- `clues`（已获线索 id 列表）、`conditions`（状态，如「重伤:…」「永久疯狂」）、`gold`——正常由游戏写入，初始可为空/0。

## 5. 派生与状态关系（引擎口径）

- 建卡时：`sanity.current/max = derived.SAN`；`state` 由后端补齐。
- 游戏中：检定用 `derived.SAN`（理智检定成功 = 掷骰 ≤ SAN）；HP/SAN 变动经 `state_apply` 校验（越界拒绝）后写回 `state` 与 `sanity.history`。
- 前端展示：角色页读 `attributes/derived/skills/inventory/sanity.history/meta.occupation`；游玩页角色栏读 `state.hp/san + derived`。

---

## 6. 技能表

`skills` 对象：**英文技能名**（键）→ 数值（0–99；可超 99 如信用评级，但建议 ≤99）。与前端搜索分组（战斗 / 社交 / 学术 / 其他）对应的完整默认表（引擎自动生成值）：

| 组 | 技能（默认值） |
|---|---|
| 战斗 | Dodge 30 · Fighting(Brawl) 25 · Firearms(Handgun) 20 · Firearms(Rifle) 25 · Throw 20 |
| 社交 | Charm 15 · Fast Talk 5 · Intimidate 15 · Persuade 10 · Psychology 10 · Art/Craft 5 · Disguise 5 · Credit Rating 0 |
| 学术 | First Aid 30 · Spot Hidden 25 · Climb 20 · Drive Auto 20 · Library Use 20 · Listen 20 · Stealth 20 · Swim 20 · Elec Repair 10 · Mech Repair 10 · Navigate 10 · Track 10 · Appraise 5 · History 5 · Law 5 · Occult 5 · Anthropology 1 · Archaeology 1 · Locksmith 1 · Medicine 1 · Cthulhu Mythos 0 |
| 其他 | Jump 20 · Language(English) 20 · Natural World 10 · Sleight of Hand 10 · Survival 10 · Accounting 5 · Ride 5 · Language(Other) 1 · Op Hvy Machine 1 · Pilot 1 · Psychoanalysis 1 · Science 1 |

> - **键名请用英文**（与引擎默认一致）；若用中文键（如「侦查」），前端分组会按关键词识别，但**引擎默认值对照与自由检定建议用英文名**。
> - 可自定义技能（如 `"Science(Biology)": 30`）；数值缺失的技能按缺失处理（检定 target 以角色卡为准，缺则视为 0）。

## 7. 上传方式

### 7.1 前端（推荐，玩家场景）

1. 加入游戏后进入「角色」页 → 建卡三步 → 选「手动填写」或直接用 `action: auto`（AI 生成）。
2. 若要上传自定义 JSON：**当前 UI 未提供 JSON 粘贴框**（已知限制），请用 7.2 的 API 直传，或在「手动填写」中录入属性后补充技能。

> 若希望前端加「JSON 粘贴上传」入口，可作为后续增强（M9 候选）提需求。

### 7.2 API 直传（保证「直接上传写入」）

```bash
# 需先有玩家令牌 X-Player-Token（加入房间后由 /join 返回）
curl -X POST "http://127.0.0.1:18000/api/games/<游戏号>/characters" \
  -H "Content-Type: application/json" \
  -H "X-Player-Token: <你的玩家令牌>" \
  -d '{"character": <角色卡 JSON>, "name": "角色显示名"}'
```

响应 `200` 即写入成功（返回完整角色卡）；`name` 可省（默认用玩家名）。成功后刷新角色页/游玩页即可看到。

## 8. 用 AI 生成角色卡（玩家提要求的标准姿势）

玩家把想法交给任意 LLM，**要求它按 coc7-character/v1 输出 JSON**。建议提示词模板：

```text
请为《克苏鲁的呼唤 7 版》生成一张 CoC7th 调查员角色卡，
必须输出严格符合以下 JSON 结构的 coc7-character/v1 角色卡（不要任何其它文字）：

- schema: "coc7-character/v1"
- name 与 cn：我的角色名 / 中文名
- meta.occupation：我的职业
- attributes：STR/CON/SIZ/DEX/APP/INT/POW/EDU/LUK 九项，百分制 3-99（POW 也是百分制）
- derived：HP=ceil((CON+SIZ)/10)、MP=ceil(POW/5)、SAN=POW（不要乘 5！）、DB 按 STR+SIZ 查表、MOV=8（规则修正）
- skills：英文技能名键（如 Spot Hidden、First Aid），按我的职业给合理值
- inventory / notes：物品与背景
- sanity: current/max 都等于 SAN
- state: hp/max_hp 等于 HP，san/max_san 等于 SAN，clues/conditions 空数组，gold 0

我的要求：
1. 职业：私家侦探，1920 年代
2. 角色背景：沉默寡言、擅长观察，曾在欧洲战场做过勤务兵
3. 属性侧重：侦查、意志高，体质稍低
4. 给我 3 个属性分配方案（稳健 / 冒险 / 均衡），并把每个方案的完整 JSON 都输出
```

**生成后自检（务必，见 §9 清单）**：重点检查 `SAN` 是否等于 `POW`（常见错误是乘 5）、`skills` 是否英文键、`derived` 是否与 `attributes` 自洽。然后把 `{"character": <AI 输出的 JSON>, "name": ...}` 按 §7.2 上传。

## 9. 校验清单与常见错误

### 9.1 上传前自检清单（逐项打勾）

- [ ] `schema` === `"coc7-character/v1"`
- [ ] `attributes` 九个键齐全（STR/CON/SIZ/DEX/APP/INT/POW/EDU/LUK），值 ∈ 3–99
- [ ] `SAN` === `POW`（**禁止 POW×5**）
- [ ] `HP` === `ceil((CON+SIZ)/10)`，`MP` === `ceil(POW/5)`
- [ ] `DB` 字符串与 STR+SIZ 查表一致
- [ ] `skills` 全部为英文键
- [ ] `sanity.current/max` === `derived.SAN`
- [ ] `state`（若提供）的 `max_hp/max_san` 与 `derived.HP/SAN` 一致；`hp ≤ max_hp`、`san ≤ max_san`
- [ ] JSON 语法合法（可用 `python -m json.tool` 或 AI 自检）

### 9.2 常见错误

| 错误 | 后果 |
|---|---|
| `SAN = POW × 5` | 理智检定恒成功、SAN 永不损失（引擎已修复，模板/提示词需同步） |
| 技能用中文键 | 引擎默认对照与部分检定失配；分组仍按关键词识别 |
| 缺 `schema` / 键名拼错（如 `Str`） | 前端/后端按缺失处理，属性显示 — |
| `HP` 与属性不符 | 状态段以 `derived.HP` 为上限，显示偏差 |
| JSON 末尾多逗号 / 引号不闭合 | 上传 400（FastAPI 解析失败） |

## 附录 A · 与引擎自动生成的一致性

`POST /api/games/{key}/characters` 的 `action: "auto"` 即由 `server/engine/build.py` 生成：5d6×6 keep3 ×5 出属性（POW 亦百分制）、上述公式推算派生、46 项默认技能、`sanity.current/max = SAN`。**手工模板与 auto 生成的唯一差别是数值来源**（玩家定制 vs 随机），结构完全一致——这正是「AI 生成 / 模板填写 / 引擎自动」三种建卡路径可以无缝混用的原因。
